## 3. Обзор и сравнение аналогов

### Прямые аналоги

Решения, которые также реализуют диалоговый подбор товаров с визуализацией рекомендаций:

1. **Amazon Rufus** - AI-ассистент покупок в Amazon. Ведёт диалог, показывает товары, но представление характеристик фиксированное, нет явного состояния требований. Пользователь не видит на экране отдельный список своих требований, не может убрать или изменить одно требование, не переписывая всё сообщение, и не понимает, почему товар появился или исчез из подборки. Характеристики товаров для сравнения всегда показываются в одном и том же виде и не подстраиваются под конкретный запрос. https://www.aboutamazon.com/news/retail/amazon-rufus
2. **Google Shopping AI** - диалоговый подбор товаров с карточками и сравнением. При сравнении товаров система показывает свой набор характеристик, но пользователь не понимает, почему выбраны именно эти характеристики и почему их нельзя изменить под свой запрос. Если важной для человека характеристики нет в таблице — он её не увидит. https://shopping.google.com/
3. **Яндекс Маркет AI-консультант** - диалоговый помощник подбора товаров. Показывает карточки, но состояние требований не отображается явно. диалоговый помощник подбора товаров. На экране нет отдельного блока с текущими требованиями пользователя, поэтому непонятно, что система уже учла и что изменилось после нового сообщения. Убрать или поправить одно требование вручную нельзя — всё остаётся внутри текста чата.https://market.yandex.ru/

### Косвенные аналоги

Решения, решающие часть задачи другим способом:

1. **ChatGPT / Claude с плагинами поиска товаров** - чистый чат без специализированного UI, без карточек и сравнения. https://chat.openai.com/
2. **Интерфейсы сравнения товаров (e-katalog, Яндекс Маркет «Сравнить»)** - таблицы сравнения с фиксированным набором характеристик, без диалога. https://www.e-katalog.ru/
3. **Виджеты чат-поддержки (Intercom, Crisp)** - чат с оператором/AI, но без товарных рекомендаций и сравнения. https://www.intercom.com/

### Выводы по сравнению

- **Что можно использовать:** паттерны карточек товаров (Amazon, Яндекс Маркет), идею сравнения (e-katalog), диалоговый поток (Rufus, ChatGPT).
- **Какие ограничения устраняем:**
  - отсутствие явного состояния требований => добавляем визуальное отображение и ручное редактирование;
  - фиксированный набор характеристик => заменяем адаптивным отбором по разработанному методу;
  - привязка к конкретному магазину => делаем универсальный встраиваемый виджет;
  - отсутствие сравнения влияния интерфейса на качество выбора => проводим эксперимент с тремя режимами.

## 4. Итоги

**Итоговая тема ВКР:** Разработка адаптивного диалогово-визуального интерфейса интеллектуальной системы подбора товаров

**УДК для тезиса:** 004.514

**Ключевые слова:** адаптивный интерфейс, диалоговая система, рекомендательные системы, диалоговые рекомендательные системы, визуализация требований, сравнение товаров, встраиваемый виджет, UX-исследование

### Актуальность исследования

Актуальность обусловлена несколькими факторами:

1. **Рост диалоговых рекомендательных систем**: диалоговые рекомендательные системы становятся стандартом в e-commerce, но их интерфейсы исследованы недостаточно.
2. **Проблема «чёрного ящика» чата**: пользователю сложно понять, какие требования система уже учла и почему предложены конкретные товары. Это ведёт к ошибкам выбора и возвратам.
3. **Ограниченность существующих аналогов**: они не отображают состояние требований явно и используют фиксированный набор характеристик для сравнения, что не адаптируется под конкретный запрос.
4. **Практическая потребность** в универсальных встраиваемых консультантах, которые можно подключить к любому магазину без переписывания frontend-логики.
5. **Научная лакуна:** существующие работы исследуют алгоритмы рекомендаций и текстовые объяснения, но мало работ системно сравнивают *способы визуального представления* состояния диалога и рекомендаций и их влияние на *объективные метрики* принятия решения (время выбора, количество ошибок, пропущенные ограничения).

### Цель исследования

Разработать метод адаптивного отбора характеристик для представления и сравнения товаров в диалоговом интерфейсе интеллектуальной системы подбора товаров и экспериментально оценить его влияние на качество принятия решения пользователем.

### Задачи исследования

1. Провести обзор литературы по диалоговым рекомендательным системам, HCI и методам объяснения рекомендаций.
2. Проанализировать существующие аналоги и выявить их ограничения.
3. Сформулировать метод адаптивного отбора характеристик на основе определенной функции (значимость в запросе + способность различать товары + полнота данных + нарушение ограничения).
4. Спроектировать архитектуру встраиваемого виджета с разделением UI, состояния диалога и API-клиента.
5. Реализовать три режима интерфейса: обычный чат, чат + стандартные карточки, адаптивный интерфейс с отбором характеристик.
6. Реализовать формализованное состояние требований с возможностью ручного редактирования и сохранения между сообщениями.
7. Подготовить сценарии эксперимента и метрики оценки (доля успешных сценариев, время до выбора, количество действий, пропущенные ограничения, возвраты назад, правильность понимания причин рекомендации).
8. Провести эксперимент с участниками и статистически обработать результаты (Python / pandas / scipy).
9. Сформулировать выводы о влиянии способа представления на качество принятия решения.

### Датасеты и сервисы

- **Подсистема каталога**: API `POST /stores/{storeId}/search` для поиска товаров. Не разрабатывается в данной работе, используется как внешний сервис.
- **Диалоговый endpoint** `POST /stores/{storeId}/dialog/messages`: реализуется в рамках работы или предоставляется смежной подсистемой; принимает сообщение и состояние диалога, возвращает структурированный результат (обновлённые требования, действие, товары).
- **Собственные сценарии эксперимента**: наборы требований и товаров для четырёх сценариев покупки (ноутбук, телевизор, наушники, смартфон), часть товаров подходит полностью, часть - частично.
- **Собственные данные эксперимента**: логи действий участников (время, клики, сообщения, возвраты, финальный выбор) для статистической обработки.
- **Открытые датасеты** не требуются, так как используются реальные каталоги подключённых магазинов через API и собственные сценарии.
