## 3. Обзор и сравнение аналогов

Ниже сравнение опирается только на **публично подтверждённые и наблюдаемые свойства интерфейса**. Для закрытых продуктов не делается вывод о внутреннем хранении состояния, если это не следует из официального описания. В эксперименте ВКР сравнивается не «помнит ли система что-то внутри», а три наблюдаемых свойства: (1) есть ли отдельное видимое представление требований, (2) можно ли править отдельное требование вне свободного текста, (3) как выбираются характеристики для карточек и сравнения.

### Прямые аналоги

Решения, которые уже совмещают диалоговый подбор товаров с визуальным представлением результатов:

1. **Amazon Alexa for Shopping / Rufus** — официальный интерфейс Amazon Shopping app и сайта. По официальному описанию сервис умеет отвечать в диалоге, строить рекомендательные подборки, сравнивать товары «бок о бок», показывать цены, отзывы и историю цены. При этом отдельный редактируемый список текущих требований пользователя в описании интерфейса не показан. Официально заявлена персонализация по истории покупок и разговорам, но это не равнозначно видимому формализованному состоянию требований. https://www.aboutamazon.com/news/retail/alexa-for-shopping-ai-assistant
2. **Google Shopping / AI Mode / Gemini shopping** — официальный shopping-режим Google. По описанию Google, AI Mode показывает насыщенную визуализацию, изображения с возможностью покупки и сравнительную твблицу с представлением «бок о бок»; Gemini app также умеет показывать товарные листинги, сравнительные таблицы, цены и места покупки. Однако отдельная панель распознанных требований и ручное редактирование каждого требования в интерфейсе не описаны. https://blog.google/products/shopping/agentic-checkout-holiday-ai-shopping
3. **ChatGPT Search / Shopping** — официальный shopping-режим ChatGPT на web и mobile. OpenAI прямо указывает, что ChatGPT может показывать товары с изображениями и деталями, а также сравнивать продукты, объяснять компромиссы и уточнять выбор. В документации указано, что на подбор могут влиять запрос и контекст (включая память и кастомные инструкции), но отдельного видимого и редактируемого списка распознанных требований официальное описание не содержит. https://help.openai.com/en/articles/11128490-shopping-with-chatgpt-search
4. **Яндекс Маркет: ИИ-агент для покупателей** — официальный ИИ-агент Маркета. По описанию Яндекса, агент работает в чате, в поиске, на карточке товара и на экране сравнения; умеет учитывать контекст диалога, сравнивать товары и объяснять различия. При этом в официальном описании не показан отдельный редактируемый блок текущих требований пользователя. https://yandex.ru/company/news/18-12-2025-04

### Косвенные аналоги

Решения, решающие часть задачи другим способом:

1. **Классические интерфейсы сравнения товаров (e-katalog, обычный режим «Сравнить» на маркетплейсах)** — дают таблицу характеристик, но обычно не поддерживают диалоговое уточнение требований. https://www.e-katalog.ru/
2. **Виджеты чат-поддержки (Intercom, Crisp)** — дают разговорный интерфейс, но не ориентированы на структурированное сравнение товарных альтернатив и объяснение различий между ними. https://www.intercom.com/
3. **Обычный поисковый листинг магазина** — хорошо поддерживает фильтры и сортировки, но не объединяет их с диалоговым извлечением требований и объяснением рекомендаций в одном окне.

### Выводы по сравнению

- **Что можно использовать:** паттерны карточек и списков товаров, режимы side-by-side comparison, диалоговое уточнение требований и сценарии объяснения различий между товарами.
- **Какие ограничения устраняем:**
  - требования пользователя остаются «растворёнными» в чате => добавляем отдельное визуальное отображение и ручное редактирование;
  - характеристики для сравнения выбираются системой без явного контроля пользователя => заменяем адаптивным отбором по разработанному методу и показываем, почему выбраны именно эти признаки;
  - привязка к конкретному магазину => делаем универсальный встраиваемый виджет;
  - отсутствие контролируемого сравнения влияния интерфейса на качество выбора => проводим эксперимент с тремя режимами на одинаковых товарах и одинаковых ответах рекомендательной логики.

## 4. Итоги

**Итоговая тема ВКР:** Разработка адаптивного диалогово-визуального интерфейса интеллектуальной системы подбора товаров

**УДК для тезиса:** 004.514

**Ключевые слова:** адаптивный интерфейс, диалоговая система, рекомендательные системы, диалоговые рекомендательные системы, визуализация требований, сравнение товаров, встраиваемый виджет, UX-исследование

### Актуальность исследования

Актуальность обусловлена несколькими факторами:

1. **Рост диалоговых рекомендательных систем**: диалоговые рекомендательные системы становятся стандартом в e-commerce, но их интерфейсы исследованы недостаточно.
2. **Проблема «чёрного ящика» чата**: пользователю сложно понять, какие требования система уже учла и почему предложены конкретные товары. Это ведёт к ошибкам выбора и возвратам.
3. **Ограниченность существующих аналогов**: даже когда у них уже есть карточки товаров и сравнение side by side, официальные описания обычно не показывают отдельное редактируемое представление текущих требований пользователя, а набор характеристик для сравнения выбирается системой и не задаётся как прозрачный объект интерфейса.
4. **Практическая потребность** в универсальных встраиваемых консультантах, которые можно подключить к любому магазину без переписывания frontend-логики.
5. **Научный пробел:** существующие работы исследуют алгоритмы рекомендаций и текстовые объяснения, но мало работ системно сравнивают *способы визуального представления* состояния диалога и рекомендаций и их влияние на *объективные метрики* принятия решения (время выбора, количество ошибок, пропущенные ограничения).

### Цель исследования

Разработать метод адаптивного отбора характеристик для представления и сравнения товаров в диалоговом интерфейсе интеллектуальной системы подбора товаров и экспериментально оценить его влияние на качество принятия решения пользователем.

### Задачи исследования

1. Провести обзор литературы по диалоговым рекомендательным системам, HCI и методам объяснения рекомендаций.
2. Проанализировать существующие аналоги и выявить их ограничения.
3. Сформулировать метод адаптивного отбора характеристик для представления и сравнения товаров на основе функции вида:

### Датасеты и сервисы

- **Подсистема каталога**: API `POST /stores/{storeId}/search` для поиска товаров. Не разрабатывается в данной работе, используется как внешний сервис.
- **Диалоговый endpoint** `POST /stores/{storeId}/dialog/messages`: реализуется в рамках работы или предоставляется смежной подсистемой; принимает сообщение и состояние диалога, возвращает структурированный результат (обновлённые требования, действие, товары).
- **Минимальный каталог для одного сценария**: не менее 8 товаров одной категории; из них 2 товара полностью удовлетворяют обязательным ограничениям, 3 нарушают по одной важной характеристике, 3 являются правдоподобными отвлекающими альтернативами.
- **Собственные сценарии эксперимента**: наборы требований и товаров для четырёх сценариев покупки (ноутбук, телевизор, наушники, смартфон). Для каждого сценария заранее фиксируются набор товаров и одинаковые ответы рекомендательной логики для трёх режимов интерфейса.
- **Резервный набор на случай недоступности смежного API**: локальный JSON-снимок тех же товаров и заранее подготовленные ответы диалогового endpoint, чтобы провести сравнение режимов офлайн без изменения сценариев.
- **Собственные данные эксперимента**: логи действий участников (время, клики, сообщения, возвраты, финальный выбор) для статистической обработки.
- **Открытые датасеты** не требуются, так как используются реальные каталоги подключённых магазинов через API и собственные сценарии.
